## 三、合理的登场叙事

时间线完成并点击“聆听另一个我的回应”后，不要立刻出现人物和聊天框。按下列顺序执行：

1. 输入区暂时锁定，页面进入 `opening`。
2. 飞船舱门的琥珀色暖灯轻微增强。
3. “现在的我”从飞船舱门/舷梯方向出现，以像素阶梯位移沿坡面走下。
4. 人物双脚落到月面后移动至最终交流位置，进入 `grounded`。
5. 月面另一侧出现克制的冷青扫描柱，进入 `manifest`。
6. 光点从脚部向上聚合，逐段形成“另一个我”的腿、身体、手臂与头部。
7. 扫描柱淡出，保留半透明投影、横向扫描缺口和极低频像素错位，进入 `settle`。
8. 首个“另一个我”对话框出现，输入框恢复，进入 `ready`。

## 四、两个人物的视觉区别

### 现在的我

- 完全不透明的实体人物。
- 深灰黑衣物，接受少量飞船暖光和银河冷色边缘光。
- 有接触阴影，脚底与月面贴合。
- 不使用全身光效。

### 另一个我

- 与玩家使用相似轮廓，体现“另一个自己”，但不是普通真人 NPC。
- 主体透明度约 72%–82%。
- 冷青、冰蓝和少量月白轮廓。
- 保留细窄横向扫描线、1–2px 偶发水平错位和少量脱落光点。
- 脚底可有很弱的冷青接触环，但不能污染大片地面。
- 禁止做成鬼魂、机器人、不同物种或完整真人肤色人物。

两个人物使用侧面或三分之四侧背角度彼此相对。人物高度仅占画面约 7%–10%，其作用是确认说话方，不抢夺文字焦点。

人物脚下禁止出现“玩家输入”“LLM 回应”“NPC”“AI”等说明。身份只写在各自对话框标题内。

## 五、对话框设计

沿用完整交替对话历史，但把普通网页聊天条改成精致的像素游戏对白框：

- “另一个我”靠左，冷青边框。
- “现在的我”靠右，暖金边框。
- 深黑蓝半透明底色，透明度约 90%，正文保持暖白色。
- 使用 1px 主边框、小圆角和短尾巴，避免大光晕。
- 宽度随文字增长，桌面最多 26% 画宽、上限 420px。短句缩小，长句向上展开，不移动底部锚点。
- 桌面两人约位于画面 43% / 60% 处，气泡向外侧展开；尾巴水平中心对准说话人，尖端距可见头顶约 10px。
- 现场仅显示每一方最新一句，不用上下堆叠的远距离聊天面板。输入等待时由同一 NPC 锚点显示思考气泡，不重复发送请求。
- “回看对话”切换到完整交替历史列表，“回到人物对话”恢复现场。不得删除任何历史记录或改变上下文。
- 极长回复保留全文，限制气泡高度并提供触摸和键盘阅读，不能撑出屏幕或遮挡人物。

底部输入区保持紧凑，只保留输入框、“告诉他”和“结束对话”。主按钮继续使用项目既有暖金高亮，不增加多余工具栏。

## 六、交互状态与跳过

使用明确状态控制：

```text
idle → opening → threshold → disembark → grounded → manifest → settle → ready
```

- `opening` 至 `settle` 期间不创建输入框或禁用发送，避免用户误触。
- 显示一句简短状态文案和“跳过相遇动画”。
- 点击跳过或在输入未聚焦时按 Space，立即幂等收束到 `ready`。
- 跳过只跳过登场动画，不能跳过首句、不能发送请求、不能改变 transcript。
- 正常完成或跳过后，首句都只能出现一次。
- 输入框获得焦点后，Space 必须正常输入空格，不能触发跳过。
- 场景隐藏、返回或重新进入时，取消登场帧循环并重置状态，避免旧动画污染下一次进入。

## 七、说话反馈

- 玩家聚焦或输入时，“现在的我”只做一次 1–2px 的轻微点头/身体起伏。
- LLM 等待和回复时，“另一个我”的冷青轮廓略微增强，扫描线低频移动。
- 不使用持续大幅挥手、快速闪烁、镜头震动或大面积 Bloom。
- 银河、人物、投影和对话框使用不同节奏，避免全画面同时运动。

## 九、Reduced Motion 与性能

- 尊重 `prefers-reduced-motion: reduce`。
- Reduced Motion 下跳过逐帧走路、粒子上升和循环扫描，直接显示最终实体与稳定投影，并开放输入。
- 粒子优先使用少量 CSS 多重径向渐变、伪元素或单 Canvas 层，不持续创建大量 DOM 节点。
- 全屏人物和特效层保持 `pointer-events: none`，仅角色的小范围反馈按钮可交互，不阻挡输入和导航。
- 使用 `image-rendering: pixelated`，关闭人物素材平滑插值。
