# 人生回测：第二幕新五问、个性化推荐与第四幕访谈

日期：2026-09-11  
项目：Past-Forward（`Past-Forward-main`）  
状态：待实现；本文是已对齐的设计，不是交接总册的现状描述

## 1. 目的

玩家走完海边、档案局、月面花园之后，在三岔口点「进入回溯」，进入独立第四幕：先从知乎公开检索里点一位「平行宇宙的他」，再按关键人生节点做引导式访谈。回测的交付物是一份测量报告，整理每次选择的**选择内容｜主观动因｜客观约束｜备选方案**，并归纳约束倾向、价值观、语言风格、决策模式、优先项和对困境的看法。

报告按信息是否采全触发，不按固定轮次。完整报告只在全部节点校验通过且收尾确认之后生成；玩家可随时要求阶段性报告。

## 2. 范围

做：

- 第二幕五问改为：年龄、性别、学历、身体状况、重大人生事件
- 回溯起点从重大人生事件解析；解析不出则补年龄
- 第三幕知乎检索改用新五问做个性化查询（不另做推荐引擎）
- 独立第四幕：候选人 → 访谈 → 报告；构图沿用现有「另一个我」月面舞台
- 本地访谈状态机（四格 + 交叉核验 + 简略追问）
- 本机后端：候选人 / 人设包 / 对话 / 报告；对话模型为 OpenAI 兼容 `gpt-4o-mini`

不做：

- 玩家知乎 OAuth、直答、给真实用户发私信
- 预测未来、把模拟影像或「他」写成真人经历
- 重做第一幕、门时间轴、花朵生命周期
- 把对话叠进花园主 UI 或做成独立网站聊天页
- 把密钥写进前端、仓库或日志

## 3. 玩家流程

```text
第一幕 海岸 → 穿梭
第二幕 档案局五问（新字段）→ 审查 → 出门
第三幕 种花到现年 → 三岔口
第四幕 候选人 2–3 人 → 点一位 → 按 K 个节点访谈
      → 自动：K 全完成 → 收尾确认 → 完整报告
      → 手动：随时「生成报告」→ 进度 + 阶段性或继续聊
```

第四幕入口：花园走到现年并进入三岔口后，点「进入回溯」。不再留在现有裂隙脚本页里改文案，而是切到独立第四幕。左下「返回三岔口」随时可走，访谈进度写入本机，不丢。

## 4. 第二幕登记

检查点位置和走路方式不变，只换题目与字段。

| 顺序 | 字段 | 问题 | 输入 | 校验 |
| --- | --- | --- | --- | --- |
| 1 | `age` | 先告诉我，你现在几岁？ | 数字 | 10–100 |
| 2 | `gender` | 你如何描述自己的性别？ | 仅按钮 | 只能选「男」或「女」；无手写、无「非二元」、无「不透露」 |
| 3 | `education` | 你目前的学历是什么？ | 按钮，可补「其他」一句 | 高中及以下 / 专科 / 本科 / 硕士 / 博士 / 其他；选其他必须写内容 |
| 4 | `health` | 你现在的身体状况怎样？ | 按钮，可补一句 | 良好 / 一般 / 慢性病或长期不适 / 不透露；补句可选，上限 80 字 |
| 5 | `lifeEvent` | 对你影响最大的人生事件是什么？ | 自由写 | 非空，上限 80 字；鼓励带年龄 |

类型：

```ts
type ArchiveQuestionId = 'age' | 'gender' | 'education' | 'health' | 'lifeEvent'
type ArchiveProfile = Partial<Record<ArchiveQuestionId, string>>
```

旧字段 `family` / `status` / `rewind` 不再采集。`cleanProfile` 只保留新五键。读到旧五问或键不一致时按新局处理，不把上一份花园进度套给新登记。调试档 `GARDEN_DEBUG_PROFILE` 改为新五键；`?rewind=` 调试参数改为 `?event=`（事件原话），需要年龄时用 `?age=`。

### 4.1 回溯起点

从 `lifeEvent` 解析第一个 `N岁`（或「N 岁」）或明确的 `19xx/20xx年`。

- 解析出年龄：作为 `RewindTarget.age`，花园与访谈的 fork 起点
- 只有阶段词（「毕业那年」）：`kind: 'stage'`，进入第三幕后补问「那时你几岁」，不凭现年倒推出生年
- 完全解析不出年龄或年份：第五问提交后立刻补问「这件事发生时你几岁」；没有这个年龄不能落座出门

`parseTarget` 改为读 `lifeEvent`，不再读 `rewind`。

## 5. 第三幕个性化检索

不另写推荐引擎。继续用 `src/zhihu/recommend.ts` 的查询与解释，把 `JourneyContext.profile` 从 `family/status/rewind` 换成：

```ts
profile: Pick<ArchiveProfile, 'gender' | 'education' | 'health' | 'lifeEvent'>
```

每次 `nodes/query`、`match`、第四幕候选人检索都带上第二幕新五问。查询词权重从高到低：

1. `lifeEvent` 整句（截断后）
2. 已种下的路，越近权重越高（现有逻辑）
3. `education`：仅当节点年龄 ≥ 16
4. `health`：有具体文本时进入（含「良好」；「不透露」除外）
5. 年龄继续作为节点岁数；性别「男／女」作为独立查询词，不与「考研」「当兵」粘成一句

禁止把性别粘在选择词前面，例如单独搜「女 考研」。推荐理由必须能指回玩家写过或种过的词；对不上就写重合还浅，不编匹配分数，不用性别或身体状况编命运。

知乎失败：第三幕继续回退作者骨架 / 演示帖，并标明不是真实匹配。第四幕候选人同样回退，见第 7 节。

## 6. 节点清单 K

进入第四幕时生成本局只读清单，之后不增删。玩家新聊出的细节只填格子，不加第 K+1 个节点。

合并去重规则（按年龄）：

1. 第三幕主线已种的每朵花：`{ id, age, title }`，`title` 为花的 `label`
2. `lifeEvent` 解析出的年龄若还没有节点，补一条，`title` 为事件原话（截断）
3. 若仍为空：回溯起点年龄（若有）+ 现年，至少 1 个节点

例：种了 18 择校、20 入伍、22 返校，事件写「24 岁考研」→ K=4。

## 7. 第四幕场景

独立场景，不塞进花园主 UI。构图沿用现有「另一个我」月面舞台：

| 区域 | 用途 |
| --- | --- |
| 月面舞台（地球、舱体、两朵花、两人） | 左：玩家；右：选中的「他」。未选人前右侧是未点亮剪影 |
| 左下「返回三岔口」 | 离开并保存访谈进度 |
| 右上出处抽屉 | 标题固定为「这句话来自哪些真实经历？」；只放该候选人公开原文；失败不给假链接 |
| 底部对话匣 | 候选人阶段列 2–3 人；开聊后为「你 / 另一个我」多轮输入 |
| 「个人标签」 | 保留入口，不承担访谈或报告 |

三个节拍不换底图：候选人 → 访谈 → 报告（报告为舞台上的全宽层）。

现有裂隙里「给另一个我选一条路」的脚本走法，第四幕不再使用。

### 7.1 候选人

进入第四幕时请求 `POST /api/life/candidates`。按作者去重，取 2–3 人。每人：显示名、一句重合理由、一句原文摘录。

玩家点一位后请求 `POST /api/life/persona`，拉齐该作者公开帖，做成截断人设包（约 8 条，每条截断）。不生成头像。不用知乎直答。

检索失败：仍展示 2–3 个演示候选人，卡片标明「演示 · 不是真实匹配」。可以进入访谈；人设包为空，系统提示仍用平行宇宙规则，对话匣顶标注演示；出处抽屉不给假 URL。

「他」不是答主本人，只是被这些公开文字约束出来的平行自我。UI 必须保持这句区分。

## 8. 访谈状态机

每个节点四格 + 交叉核验：

| 键 | 通过 | 不通过（必须追问） |
| --- | --- | --- |
| `choice` | 当时选了什么，能对上节点标题或玩家原话 | 「就那样吧」「忘了」 |
| `motive` | 价值观 / 情绪 / 诉求至少一类 | 只有选项名，没有「为什么」 |
| `constraint` | 家庭、收入、机会、地域、身体、信息等至少一类 | 完全没提限制 |
| `alternative` | 当时至少还有一条没走的路 | 「没得选」且未说明为何没得选 → 追问是真没选项还是没看见 |
| `agency` | 「主动偏好」或「条件妥协」或「两者都有、以谁为主」 | 还没问过这句 |

节点状态：`pending` → `interviewing` → `complete`。

简略规则（本地，不靠模型自觉）：该格有效文本短于 8 个汉字，或整句等于/含「还好」「不知道」「随便」「忘了」（去掉标点后），标 `sparse`。`sparse` 时：

- 节点不得标 `complete`
- 下一句必须是针对缺格的补问
- 不得自动提起报告

数字人规则（灌进系统提示，状态机强制）：

- 用 Z 的口吻，不要变成通用 AI
- 自然带出：曾经站在一样的路口，但走向不同方向
- 每次只问一个开放问题
- 保持好奇，不评判对错
- 听完可简短复述再提问
- 不准在回复里出现「知乎、文本素材、检索」
- 不要泄露底层来源

对话顺序由状态机指定缺格，模型只负责把下一问说成 Z 的口吻。

### 8.1 出报告条件

**自动（须全部满足）：**

1. K 个节点都是 `complete`（打开该节点后，四格与 `agency` 均通过。场景还原不是单独一格，而是从 `choice` 对上该年事件开始聊）
2. 每个节点四格与 `agency` 都通过，且无未处理的 `sparse`
3. 没有「很简略却标完成」的节点

满足后先插入收尾问句（Z 口吻，文案固定，不由模型改写）：

> 所有分叉点我们都聊完了。回过头看，有没有哪一个选择，现在回头看，还有当时没提到的考量？确认之后，我就整理完整报告。

玩家确认「没有了 / 可以整理」之后，再问：

> 我们已经聊完了你人生所有关键分叉点。现在我可以整理一份完整报告，汇总你每一次选择背后的想法与当时的客观条件，需要生成吗？

玩家同意才生成完整报告。收尾未确认不得出完整报告。

**手动：** 玩家发送「现在生成报告」「总结一下」或点同等按钮。系统先报进度，例如：

> 目前我们完成了 2/4 个节点的访谈，18 岁择校、20 岁入伍的信息收集完毕；22 岁返校、24 岁考研还没有深入聊。你可以选择：① 先输出一份不完整的阶段性报告；② 继续聊剩下节点，等全部完成再生成完整报告。

不因手动触发直接写出完整报告。

## 9. 报告

盖在第四幕舞台上。不占用「个人标签」面板。

**完整报告**

- 页眉：年龄、学历、身体状况、重大人生事件原话；候选人显示名；固定声明「根据你亲口说的整理，不是命运预测」
- 每个已完成节点一张表：选择内容｜主观动因｜客观约束｜备选方案 + `agency` 标签
- 格子只使用玩家原话或抽槽后的短句，不补没说过的内容
- 文末六条，只从已完成节点归纳：客观约束倾向、看重的价值、语言风格、决策思考模式、优先考虑什么、遇到困境的看法
- 可关闭回对话匣；可回三岔口；本机可再打开同一份

**阶段性报告**

- 标题必须含「不完整 · n/K」
- 已完成节点同上表
- 未完成节点只列缺失格，正文留空，禁止模型编造
- 提供「继续聊剩下的节点」

## 10. 后端与密钥

知乎只找人和拿公开文字。开口和出报告走 OpenAI 兼容接口。

| 路径 | 作用 |
| --- | --- |
| 现有 `POST /api/life/match` | 公开搜索 |
| 现有 `GET /api/life/author` | 按作者名拉公开帖 |
| 现有 `POST /api/life/nodes/query` | 第三幕选项发现 |
| 新增 `POST /api/life/candidates` | 按花园进度 + 新五问出 2–3 人 |
| 新增 `POST /api/life/persona` | 选定作者后做成截断人设包 |
| 新增 `POST /api/life/dialogue` | 抽槽 → 更新状态机 → 生成下一问或触发检查 |
| 新增 `POST /api/life/report` | 只根据已 `complete` 的格子出报告 |

`dialogue` 一次请求顺序固定：抽槽 → 状态机 → 若未完成则生成一个问题 → 返回节点状态。模型失败时对话匣显示重试，不编「他」的下一句。抽槽失败则本句不入格，继续追问，保留已有格。切候选人、回三岔口、关报告时取消或丢弃迟到响应。

环境变量（本机，不提交）：

- 知乎 Access Secret：继续只进本机钥匙串 / `ZHIHU_ACCESS_SECRET`，步骤见 `docs/ZHIHU_SETUP.md`
- `OPENAI_BASE_URL`（默认 `https://api.openai-next.com`；请求 `POST {OPENAI_BASE_URL}/v1/chat/completions`）
- `OPENAI_API_KEY`
- `OPENAI_MODEL`（默认 `gpt-4o-mini`）

前端不得出现上述密钥。示例文件只写变量名。自动化测试默认不打真实知乎、不打真实模型。

本机存储：

- 第二幕：`life-backtest.archive-profile`（session + local，新五键）
- 第三幕：`life-backtest.garden.v2` 的 `profile` 改为新五键；键不一致视为新局
- 第四幕：`life-backtest.interview.v1`（节点状态、对话摘要、候选人 id、报告缓存）
- 清站点数据即丢；无服务器账号

## 12. 验收与测试

单元测试（夹具，不打真实接口）：

1. 聊完 K-1 个节点时自动触发为假；完整报告接口拒绝
2. 某格短于 8 字或命中简略词 → 节点仍为 `interviewing`，下一动作是补问
3. 四格都有但缺少 `agency` → 不能 `complete`
4. 手动「生成报告」返回进度和两个选项，不直接给完整报告
5. 收尾问句未确认 → 不出完整报告
6. 性别只有男/女；其他字符串校验失败
7. `lifeEvent` 含「18岁…」则目标年龄为 18；解析不出则挡在补年龄
8. 第三幕查询含事件原话、性别、身体状况；学历在 ≥16 岁节点出现；查询中不出现「女 考研」这种粘连
9. 旧档 `family/status/rewind` 与新五键不一致 → 新花园，不恢复多种植

浏览器主路径（夹具模型/知乎）：五问（新字段）→ 种花到现年 → 三岔口进入回溯 → 点候选人 → 对话匣可输入。不消耗真实额度。
